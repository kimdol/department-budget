# 직원 신청함 사용 안내와 무안내 체험 기록

교육비 신청 한 건에는 직원, 부서장, 재무 담당자의 차례가 있다. **정산 검토**가 뜨면 직원의 제출이 접수되어 재무팀으로 넘어간다. **정산 완료**는 재무 담당자가 증빙을 확인하고 실제 집행액을 확정한 상태다. [공개 직원 신청함](https://129-225-133-96.sslip.io/?view=employee)

## 첫 방문자 체험 결과

| 항목 | 2026년 11월 22일 체험 |
| --- | --- |
| 참가자와 환경 | 이 신청함을 처음 쓰는 사람 1명. 이 PC의 로컬 신청함과 H2 시험 DB를 사용했다. |
| 시작 | 직원 역할. ‘직무 교육 참가’ 한 건에 재무팀이 지출 영수증 보완을 요청한 상태였다. |
| 수행 | 진행자 보고에 따르면 참가자가 중간 안내 없이 영수증을 첨부하고 다시 제출했다. 같은 신청에 ‘정산 검토’가 표시됐다. |
| 소요 시간 | 진행자 보고 약 40초. 화면을 건네기 전의 사례 준비와 재무팀의 최종 정산은 측정 범위 밖이다. |
| 관찰 범위 | 망설인 지점과 정확한 화면 크기는 기록되지 않았다. 이전 참가자는 안내를 받았고 측정 방식도 달라 전후 개선율을 산출하지 않았다. |

## 같은 체험을 다시 진행하는 법

**진행자가 미리 준비한다.** 새 참가자용 브라우저 세션에서 일반 기업 경영지원팀을 선택하고 **내 신청함 시작**을 누른다. 기존 세션에서 **내 체험 종료** 후 다시 시작해도 빈 공간이 열리므로 아래 업무를 한 번 만들어야 한다. 준비가 끝난 탭을 그대로 건넨다. 다른 브라우저로 주소만 보내면 방문자 공간이 달라진다.

1. 직원으로 **직무 교육 참가** 교육비 300,000원, 기간 1일을 신청한다. 부서장으로 바꾸고 같은 신청을 **사전승인**한다.
2. 직원으로 돌아가 실비 225,000원을 **증빙 없이** 정산 신청한다. ‘정산 검토’가 뜨면 재무 담당자로 바꾼다.
3. **보완 사유**에 ‘지출 영수증을 첨부해 주세요.’를 쓰고 **보완 요청**을 누른다. 직원 역할로 돌아가 목록에서 ‘보완 요청’이 한 건인지 확인한다.

**참가자에게는 아래 한 문장만 전달한다.** 버튼 이름과 순서는 진행자만 본다.

> 재무팀이 교육비 영수증을 요청했습니다. 보완하고 다시 제출해 주세요.

화면을 건넬 때부터 같은 신청에 **정산 검토**가 표시될 때까지 시간을 잰다. 영수증에 ‘첨부됨’만 뜨면 아직 제출 전이다. 처음 사용하는지, 기기·화면 폭, 경과 시간, 마지막 상태, 망설인 지점과 도움을 준 시점을 기록한다. 도움이 필요하거나 도중에 멈춘 경우에도 그대로 남긴다. 성공 후에는 진행자가 이어서 정산하거나 체험을 종료할 수 있다.

## 대표 업무를 처음부터 끝까지 따라가기

기본 교육비 규정은 지원율 80%, 행사당 한도 200,000원이다. 같은 부서와 신청번호를 유지하며 **시연 역할**만 바꾼다. 체험에는 합성 증빙을 사용한다.

| 차례 | 담당자가 하는 일 | 확인할 결과 |
| --- | --- | --- |
| 1. 접수 | 직원이 신청명·비목·예정 금액·기간을 입력한다. **지원 예정액 확인** 후 **신청 제출**을 누른다. | 예정액 300,000원에서 지원 예정 200,000원, 예상 본인 부담 100,000원. 접수 후 ‘결재 대기’, 가용액 1,000,000원. |
| 2. 약정 | 부서장이 같은 신청의 **사전승인**을 누른다. | ‘약정 완료’. 200,000원을 확보해 가용액이 800,000원이 된다. |
| 3. 실비 제출 | 직원이 상세에서 실제 지출액 225,000원을 입력하고 **정산 신청**을 누른다. 영수증이 있으면 이때 첨부할 수 있다. | ‘정산 검토’. 이 단계에서는 아직 집행액이 0원이다. |
| 4. 보완 요청 | 영수증이 빠졌으면 재무 담당자가 사유를 적고 **보완 요청**을 누른다. | ‘보완 요청’. 직원 상세에 사유가 표시된다. 증빙이 충분한 신청은 바로 6단계로 간다. |
| 5. 재제출 | 직원이 **지출 영수증 → 합성 증빙 첨부**를 누르고 ‘지출 영수증 · 225,000원 첨부됨’을 확인한 뒤 **보완 내용 다시 제출**을 누른다. | 같은 신청이 ‘정산 검토’로 돌아간다. 여기까지가 무안내 과제다. |
| 6. 확정과 조회 | 재무 담당자가 **정산 확정**을 누른다. 직원은 같은 신청에서 결과를, 재무 담당자는 전표와 결산표를 본다. | ‘정산 완료’. 약정 잔액 0원, 집행액 180,000원, 가용액 820,000원. |

실비 225,000원의 80%는 180,000원이다. 직원 본인 부담은 45,000원이고 처음 잡아 둔 약정 중 20,000원은 가용액으로 돌아간다. [요청별 API와 계산 근거](API.md) · [Oracle 전표 대조 절차](ORACLE-WALKTHROUGH.md)

## 체험할 때 어디에 어떤 데이터가 남나

새 세션에서 **내 신청함 시작** 또는 **개인 데모 시작**을 처음 누르면 기본·보조 부서의 예산 공간 두 개가 생성된다. 같은 세션에서 새로고침하거나 역할을 바꾸면 기존 공간을 사용한다. 신청함을 반복 조회하는 것만으로 신청이나 전표가 늘지는 않는다. [체험 시작](../src/main/java/kr/budget/web/DemoPortal.java) · [부서 공간 생성](../src/main/java/kr/budget/claims/ClaimService.java)

| 저장 위치 | 기록되는 시점과 내용 |
| --- | --- |
| 공개 데모의 Oracle | 신청하면 신청번호·제목·비목·금액·일수·적용 규정·요청 키가 남는다. 승인·보완·재제출 때 현재 상태는 갱신되고 결재 이력에는 역할·처리 차수·사유 등이 추가된다. 합성 증빙은 종류·금액·등록 시각을 기록하며 금액을 교체하면 변경 이력도 남긴다. 실제 영수증 이미지 업로드는 이 체험에 없다. |
| 예산 원장과 포털 | 사전승인과 정산 확정은 각각 전표와 포털 송신 기록을 남긴다. 기본 사례를 끝까지 처리하면 전표는 약정 1건과 정산 1건이다. 같은 정산 요청을 재전송해도 전표는 총 2건이다. 연계가 성공하면 MySQL에는 이벤트별 수신 이력과 해당 신청의 최신 차수·유형·금액 요약이 남는다. |
| 선택해서 처리한 업무 | 규정 검토·발행·예약, 지점 배정, 신청 수정·대체, 증빙 교체, 월마감·환입을 수행하면 해당 업무의 초안·버전·배정 기록·결산 자료·정정 전표 등이 생긴다. |
| 브라우저 | 세션 쿠키로 체험 공간을 찾는다. 신청 등 일부 요청은 응답 유실에 대비해 탭의 세션 저장소에 입력과 재시도 키를 임시 보관한다. 별도 **개인 장부**의 예산·지출명·날짜·분류·금액·지원액은 그 사이트의 브라우저 IndexedDB에 보관한다. 장부에서 개별 지출을 삭제하거나 사이트 데이터를 지울 수 있다. |

**내 체험 종료**는 세션을 종료한다. 다음 체험자는 빈 신청함으로 시작하지만 공개 DB에는 이전 공간의 업무 기록이 남는다. 저장소의 애플리케이션·배포 스크립트에서 오래된 체험 공간을 일괄 삭제하는 자동 작업은 확인되지 않았다. 이번 40초 체험은 로컬 메모리 H2에서 진행해 해당 실행이 종료되면 그 업무 데이터도 사라진다. 참가자의 망설임이나 완료 시간은 업무 DB가 수집하는 항목이 아니며, 약 40초는 진행자가 알려준 값이다. ## 기기별 동작과 검증 근거

- 넓은 화면에서는 목록과 상세를 함께 본다. 좁은 화면에서는 신청을 열어 상세로 들어가고, 목록으로 돌아오면 상태 필터·스크롤 위치·선택한 행의 키보드 포커스가 복원된다. 조회 중에는 이전 행의 선택을 막는다. [목록](../frontend/src/inbox/ClaimList.tsx) · [상세](../frontend/src/inbox/ClaimDetail.tsx) · [화면 전환](../frontend/src/inbox/EmployeeInbox.tsx)
- 첨부 처리 중에는 중복 클릭을 막는다. 응답이 끊기면 서버의 증빙 목록이나 신청 상태를 다시 읽어 접수 여부를 확인한다. 확인에 실패하면 입력을 유지해 재시도할 수 있다. [증빙 폼](../frontend/src/inbox/SettlementForm.tsx) · [키보드·지연·응답 유실 시험](../frontend/tests/employee-inbox.spec.ts)
- 공개 HTTPS 배포의 Chrome 시험에서 390·768·1440px 모두 보완부터 재무 확정과 직원 결과 조회까지 통과했다. 전체 실행은 24건 통과, 별도 실행 조건이 필요한 3건 건너뜀이다. 정산 재전송 뒤 전표 2건, 집행액 180,000원, 포털 수신액 180,000원을 확인했다. [배포 시험 원자료](measurements/deployment-workspace-sections.json)
